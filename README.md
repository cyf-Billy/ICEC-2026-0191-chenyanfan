### 为什么建仓偏晚（如实说明）

起步阶段我用的是 **Word 文档**记录课题（桌面上的 `新建 Microsoft Word 文档.docx` 就是当时的载体），不是版本库。原因有三个：

1. **当时不熟悉 GitHub**，不知道仓库能按 commit 追踪每一次改动，也不知道可以用"改前 / 改后"的对比来验证改进是否有效
2. **建仓初期遇到 GitHub 访问受阻**（账号当时处于封禁状态，无法正常登录建仓与推送），这段时间课题只能靠本地文档推进——**13 号正式开始时，仓库这条路是走不通的**
3. 我的工作方式是**边做边改**：同一份内容会在文档里反复修改——换过题、改过采样点位、改过判定阈值。Word 的问题是**一改就覆盖**：没有历史、改坏了回不去，更看不出哪一版更好

后来才想明白：Git 的价值不是"把文件传上网备份"，而是**把每次改进固化成一个可回溯的节点**——什么时候改的、为什么改、改完是不是真的更好，都能翻出来。

**代价要如实写**：11-16 到 11-23 之间的那些调整，只留在 Word 文档和记忆里，现在只能补录**结论**，补不出**过程**（比如项目一当时具体试了哪几种采集方案、失败了几次）。这部分是本项目最大的过程缺口。

**现在的做法**：

1. 外部文档（Word、截图、手写记录）里产生的内容，整理后入库，并在提交信息里写明来源
2. 课题的每次调整都记在上一节的「方案调整记录」里，一行一次
3. 拆解、采样、固件等过程数据直接写进仓库，不再用 Word 中转——**避免出现"改了 5 版但只能交最后 1 版"的情况**
