## 1. 接线表

### 1.1 经典 ESP32（如 DevKit V1 / NodeMCU-32S）

| 装置 | 板子引脚 | 说明 |
| --- | --- | --- |
| MAX9814 `OUT` | **GPIO34** | ADC1_CH6，仅输入脚，适合接模拟传感器 |
| MAX9814 `VDD` | 3V3 | 模块工作电压 2.7~5.5V，3.3V 即可 |
| MAX9814 `GND` | GND | 必须与板子共地 |
| MAX9814 `GAIN` | 悬空 | 悬空 = 60dB 增益；接 GND = 50dB；接 VDD = 40dB |
| WS2812 `DIN` | **GPIO2** | 板载 LED 同脚，便于先验证 |
| WS2812 `5V` | 5V(VIN) | 灯带要 5V，**不要接 3V3** |
| WS2812 `GND` | GND | 与板子共地 |

> ⚠️ **绝不能用 GPIO6~11**：经典 ESP32 的这 6 个脚接 SPI Flash，一接就死机。

### 1.2 ESP32-C3

| 装置 | 板子引脚 |
| --- | --- |
| MAX9814 OUT | **GPIO2**（ADC1_CH2）|
| WS2812 DIN | **GPIO8** |

固件已按芯片自动切换引脚（`config.h` 里条件编译），**换板不用改代码**。

### 1.3 若用 ESP32-CAM（摄像头板）——**实测无需改代码**

ESP32-CAM **没有板载 USB**，必须用 USB-TTL 转接座烧录。原本担心摄像头占用大量 IO，
但实际核对引脚分配后确认：**固件当前用的两个引脚在 ESP32-CAM 上都是空闲的**。

| 引脚 | ESP32-CAM 上被谁占用 | 我们的固件用它 | 是否冲突 |
| --- | --- | --- | --- |
| GPIO 0/5/18/19/21/22/23/25/26/27/32 | **摄像头**（XCLK/D0~D7/PCLK/VSYNC/HREF/SIOD/SIOC/PWDN）| — | — |
| **GPIO34** | 空闲（仅输入，可做 ADC）| **麦克风 ADC** | ✅ 不冲突 |
| **GPIO2** | 空闲 | **灯带数据** | ✅ 不冲突 |
| GPIO4 | 板载闪光灯 LED | — | 未使用 |

**编译验证（2026-11-24 实测）**：

```
& arduino-cli compile --fqbn esp32:esp32:esp32cam <固件目录>
→ Sketch uses 317517 bytes (10%)  Global variables 23260 bytes (7%)
```

**结论：直接选 `AI Thinker ESP32-CAM` 板型即可，不需要在 `config.h` 里加分支，也不需要改引脚。**

> 唯一要注意：摄像头本身**不需要接**（本装置不用摄像头），只要不初始化摄像头即可，能省下不少功耗。
> 若要保留摄像头做视觉，则 GPIO34/GPIO2 仍然是安全的。

### ESP32-CAM 的接线与进入下载模式

ESP32-CAM **没有板载 USB**，必须用 **USB-TTL 转接座**：

| USB-TTL | ESP32-CAM | 备注 |
| --- | --- | --- |
| 5V | 5V | 摄像头工作时电流较大，**建议用 5V** |
| GND | GND | 必须共地 |
| TX | **U0R**（GPIO3）| 交叉连接：TX 对 RX |
| RX | **U0T**（GPIO1）| 交叉连接：RX 对 TX |
| — | **GPIO0 → GND** | **烧录时必须短接**，烧完断开 |

**进入下载模式的两步**：

1. 用杜邦线把 **GPIO0 接到 GND**
2. 给板子**断电再上电**（或按一下 RST）——此时芯片进入串口下载模式

> 烧录完成后**务必断开 GPIO0 与 GND**，再重新上电，否则程序不会运行。

### 常见失败与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| `Failed to connect to ESP32` | 没进下载模式 | 确认 GPIO0 已接 GND，然后断电重上电 |
| 找不到 COM 口 | 驱动没装 / 线是充电线 | 装 CH340 驱动；换**数据线** |
| `Timed out waiting for packet header` | 波特率太高 | 把 `--baud 460800` 降到 `115200` |
| 烧完不运行 | GPIO0 还接着 GND | 断开 GPIO0，重新上电 |
| 摄像头初始化失败 | 供电不足 | 用 5V 而非 3.3V；换更粗的线 |

## 5. 上机验证流程（10 分钟）

| 步 | 动作 | 期望现象 |
| --- | --- | --- |
| 1 | 通电 | 灯带**红→绿→蓝**各 0.3 秒（开机自检，无串口也能确认接线）|
| 2 | 静置 10 秒 | 灯带转为**深蓝慢呼吸**（静音态，正在学基线）|
| 3 | 静置 3 分钟 | 串口打印 `[base] minute #1~#3`，基线建立 |
| 4 | 正常说话 | 灯带**青绿常亮**，串口 `state=1` |
| 5 | 大声说话 / 拍手 | 灯带**黄灯 0.5Hz 缓闪**，`state=2` |
| 6 | 持续大声（如放音乐）| 灯带**红灯 2Hz 脉冲**，`state=3` |
| 7 | 停止发声，等 2~3 秒 | 逐级回落：红→黄→绿 |
| 8 | 拔掉麦克风信号线 | 5 秒后**白灯常亮**（安全态），串口打印 `[fail] ADC saturated` |
| 9 | 插回麦克风 | 回到正常判档 |

## 7. v2.0 修了两个 bug（这次改动的价值）

### bug 1：正常工作时被误判为"麦克风失效"

**旧代码**：

```c
float ratio = fabsf((float)acc / 16.0f) / 2048.0f;   // 均值偏离偏置的比例
return ratio < ADC_FAIL_RATIO || ratio > (1.0f - ADC_FAIL_RATIO);
```

**问题**：麦克风正常工作时，输出均值**恰好就在偏置 2048 附近**，于是 `ratio ≈ 0`，
命中 `< ADC_FAIL_RATIO` → 被判成"贴底失效" → 装置永远进安全态、白灯常亮。

**新做法**：统计"贴轨样本占比"（<64 或 >4031 的比例），只有超过 90% 才判失效：

```c
float railRatio = (float)(lo + hi) / N;
if (railRatio > 0.9f) return true;
```

这样"安静"和"没接麦克风"就区分开了——**前者是正常输入，后者才是失效**。

### bug 2：驻留时间被低估约一半

**旧代码**：每次循环 `upTimer += WINDOW_MS`（10 ms），但实际一次循环耗时约
`采样 10ms + delay 10ms ≈ 20ms`，于是"要求持续 1 秒"变成实际约 0.5 秒，
**判档比设计更敏感、更容易闪**。

**新做法**：用 `millis()` 实测两次循环的差值 `dt` 来累加，与真实时间一致。

## 8. 还有一个已知限制（写在这里，不藏着）

`analogRead()` 是**阻塞采样**：一个 10 ms 窗口内 CPU 全在忙等，这期间无法处理别的事。
对本装置够用（只有一个传感器 + 一条灯带），但如果以后要加 WiFi 上报或第二个传感器，
就必须改成 **I2S 连续采样 + DMA**，否则会出现丢帧与判档抖动。
