# AI 判断与求证：一个"可能是 VPN"的猜测，让我放弃了一个工具 11 天

- 时间：约 2026-11-13 起，影响至 11-23
- 相关工具：AI 问答（DeepSeek / 豆包等）、GitHub、VPN（Clash）
- 结果：一度停用 GitHub，改用 Word 文档记录课题，建仓推迟到 11-23

## 1. 事情经过

1. 我早期注册的 GitHub 账号被平台封禁，申诉未通过
2. 我不清楚原因，就去问 AI
3. AI 的回答指向"**很有可能是开了 VPN 导致的**"
4. 我据此判断"开 VPN 会封号"，于是**干脆不敢再开 VPN**
5. 但 GitHub 在国内不开代理基本用不了——下载开发板包、推送仓库都会失败
6. 于是形成结论："GitHub 这条路走不通"，转回 Word 文档记录，一停就是十来天

## 2. 这个判断错在哪

**AI 给的是一个概率猜测，我把它当成了事实依据。**

事后看，关于"VPN 和封号"的关系，实际情况是：

| 说法 | 准确度 |
| --- | --- |
| "开 VPN 就会被封" | ❌ 不成立。GitHub 的服务条款没有禁止使用 VPN 或代理，全球大量用户通过代理访问 |
| "账号被封**可能**与所用的代理节点有关" | ✅ 这个说法才站得住——但机制不是"用了 VPN"，而是**共享 IP 的风险** |
| 真正的高风险因素 | 使用被大量滥用的**免费/公共节点**（同一 IP 上几百人）；新注册账号 + IP 频繁跨国跳变；批量注册行为 |

也就是说：**风险可能来自"用了哪个节点"，而不是"开不开 VPN"**。这两件事的应对方式完全不同——前者是换节点，后者是放弃整个工具。我选错了。

## 3. 更糟的一点：AI 的回答本身就不一致

同一个问题，我在不同时间问到的回答互相矛盾：

- 一种说法是"**VPN 不会导致封号，风险极低**"
- 另一种说法是"**很可能是 VPN 导致的封号**"

**这种前后不一致，本身就是"不能拿它当决策依据"的信号。** 涉及平台风控政策的问题，AI 的回答本质上是根据常见讨论归纳出的猜测，没有权威来源，也不会为错误负责。

## 4. 应该怎么做（正确的求证路径）

| 顺序 | 做法 | 为什么 |
| --- | --- | --- |
| 1 | **问老师** | 老师知道考核要求、也大概率知道同学踩过的坑，是最直接、能负责的信息源 |
| 2 | 查 GitHub 官方文档 / Support | 平台政策只有官方口径算数 |
| 3 | **用最小代价试验** | 换个节点、只做正常操作（建仓、提交），看会不会再出问题——成本几乎为零 |
| ❌ 不该做 | 拿 AI 的一句"很可能"当结论，直接放弃一条路径 | 代价是 11 天 |

## 5. 这次付出的代价（具体算一下）

- 11-13 正式开始课题，但仓库这条路被我判定为"走不通"
- 期间所有记录都在 Word 里，**一改就覆盖，没有历史**
- 到 11-23 建仓时，11-13～11-22 的过程已经无法完整复原，只能靠采购订单时间戳和照片水印**追溯出一部分**
- 如果当时花 10 分钟问一句老师，或者换个节点试一次，这 11 天本可以是完整、可回溯的记录

## 6. 带回的两条规则

1. **AI 对"会不会违规 / 会不会被封 / 政策怎么规定"这类问题的回答，只能当线索，不能当依据。** 这类问题的正确信息源是官方文档和负责的人。
2. **决定"放弃某个工具或路径"之前，必须做一次低成本验证。** 直接放弃是最贵的选项——它省下的是一次试验的时间，付出的是整段时间的损失。

> 顺带一个观察：这次是"AI 说可能有风险 → 我放弃工具"；而这个项目里还有另一次是"AI 编了一条不存在的约束（宿舍夜间断电）→ 我写进报告"。方向相反，性质相同：**AI 输出的东西，要过一道"这条我能不能负责"的关，再过一道"我能不能验证"的关。**
