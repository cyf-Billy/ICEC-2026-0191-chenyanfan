- 使用工具：DeepSeek（网页版 + 手机 App）、豆包（手机版 / 电脑版）
- 协作目标：在本地建好考核仓库，并推到自己的 GitHub 空仓库（实际不是空的，见下）
- 结果：推送成功，提交 `b450e07` 落在 `origin/main`

## 3. 被实测推翻的两次判断（这段最值得记）

### 推翻一：AI 说"浏览器能打开 GitHub，git 一般也能通"

- 实测：`git fetch` 卡在 `==> 拉取远程状态` 不动，最后报 `Failed to connect to github.com port 443 after 21053 ms`
- 原因：浏览器有自己的 DNS / 连接策略，**git 是直连 443**，被丢包时浏览器不受影响、git 只会死等
- 学到的：判断连通性要用 `git ls-remote <url>` 的结果，不能拿浏览器当证据

### 推翻二：AI 说"开 Clash 的系统代理就行"

- 实测：系统代理开着仍然推不上去
- 原因：**git 不读 Windows 的 WinINET 系统代理**，必须单独 `git config --global http.proxy`
- 落地：查 `clash-verge.yaml` 里的 `mixed-port: 7897`，把 git 代理指到 `127.0.0.1:7897` 才通
- 学到的：代理要分三层看——浏览器/系统代理、git 自己的代理配置、TUN 模式接管全部流量，三者不互通

### 顺带修掉的一个 AI 自身 bug

AI 为这个任务写了一个 PowerShell 推送脚本，第一版用 `$ErrorActionPreference = 'Stop'` 配合 `2>&1` 捕获 git 输出。结果 **git 打到 stderr 的每一行（推送进度、`nothing to commit` 提示）都被 PowerShell 当成致命错误**，脚本还没走到 `git push` 就崩了。改成统一的 `Invoke-Git` 封装（临时把 `ErrorActionPreference` 降为 `Continue`，单独取 `$LASTEXITCODE`）后正常。

这条我记下来的原因：**AI 给的脚本要自己跑一遍才算数**，尤其涉及错误处理和编码（脚本还得存成带 BOM 的 UTF-8，否则 PowerShell 5.1 会把中文读成乱码并报语法错）。

| DeepSeek 网页版 | 诊断链条完整，会主动去查运行状态（端口、进程、配置文件）而不是猜 | 排障类问题靠它 |

## 5. 我从这次协作里带走的规则

1. **AI 说"应该可以"时，一定要自己跑一条命令验证**，这次两处判断都是靠实测纠正的
2. **报错原文比描述有用**：`Failed to connect to github.com port 443 after 21053 ms` 这句话直接指向"直连没走代理"
3. **AI 写的脚本要复核**：错误处理、编码、路径三处最容易出问题
4. **不要把 AI 的结论直接写进报告**，先变成自己能复述的一句话再写
